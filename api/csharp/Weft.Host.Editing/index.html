    Namespace Weft.Host.Editing¶

    Classes¶

    AddComponentCommand

    Adds a component (zeroed, or with the given initial bytes; a tag has none).

    AssetKind

    One kind of asset an editor lists and picks: its type name (the of the fields that hold it), the extensions of its files and a label for a person.

    AssetKinds

    Which files are which kind of asset: the table behind the editor's asset picker and the asset field drawer. A kind is a type name (model) with the extensions of its files; a file belongs to the kind that has its extension (not case-sensitive). The engine registers model (what the model importer reads), texture (the image importer's) and scene; a package or an editor extension that adds a kind of asset (prefabs, materials) registers it with before the editor lists assets. Safe to use from several threads.

    ComponentDefaults

    What a component starts as when an editor adds it, and what Reset to default puts back: a table from the component's name to its bytes. The engine's own components have a usable value (: a with a scale of zero has no size); a component nobody registered starts as zeros, as one made in a script does. A game or an editor extension adds its own with .

    CompositeCommand

    Several commands that are one step. A composite made only of s (an inspector edit of several entities) merges with a following one that sets the same components of the same entities, so the frames of one drag are one step; any other composite never merges.

    CreateEntitiesCommand

    Makes several entities, each with its branch (pasted from the clipboard, duplicated), as one step. create returns the roots it made; undoing destroys them, and redoing brings them back under the ids they had, so the selection and the other steps of the history still point at them.

    CreateEntityCommand

    Makes an entity (with create: a new one, a clone, a model dropped into the viewport) and removes it again on undo. Redoing brings it back under the id it had.

    DestroyEntityCommand

    Deletes an entity and its branch, and brings them back under the same ids on undo.

    EditHistory

    The undo and redo history of an editor: commands are executed through it, and it can take them back and do them again. A new command after an undo drops what could have been redone. Consecutive commands that merge (the many small changes of a drag) are one step until is called, which the editor does when the gesture ends.

    FieldEditCommands

    The commands of an inspector edit that reaches several entities: some bytes of a component (a field, or the whole value) written on each of them, so that the other bytes of each keep their own values. One entity gives a plain (which merges with the next edit of the same component); several give a of them, which merges with a following one of the same targets (see ), so a drag over a field of ten entities is one step.

    InstantiatePrefabCommand

    Makes an instance of a prefab as one step: undoing destroys it, redoing brings it back under the ids it had.

    PrefabCommands

    The edits of the overrides API (World.PrefabOverrides and what follows it) as commands of an .

    PrefabStage

    One prefab opened on its own, to be edited as the prefab and not as an instance in a scene: its entities are made in a world of their own (), next to the session's, and saved back to the file with . It has no interface: a tool shows (a hierarchy, an inspector, a viewport over it), edits it with an of its own on a over , and calls .

    RemoveComponentCommand

    Removes a component, keeping its value for the undo.

    RenameCommand

    Renames an entity. Names have to be unique among siblings, so the caller checks .

    ReparentCommand

    Gives an entity a new parent (none: a root), keeping it where it is in the world by default.

    SetComponentCommand

    Changes the value of a component on an entity (an inspector field). The changes of one gesture merge: the command keeps the first "before" and the last "after".

    SetPropertyCommand

    Sets one registered property of an to a value and puts the old one back on undo, through the same setter scripts use (no reflection). The frames of one drag are one step: a following command that sets the same property of the same object folds its value in (see ). An object that has been destroyed meanwhile is left alone by undo and redo (there is nothing to put back), so a history that outlives its objects does not throw. A setter that throws on leaves the exception to the caller: records nothing in that case.

    SetTransformsCommand

    Sets the local of several entities at once: a gizmo drag over a selection. It is one step, and the frames of one drag merge into it (the command keeps the first "before" of every entity and the last "after"), as does for one entity. Only a command with the same name merges: a rotation after a move is a step of its own.

    SubtreeEditCommand

    An edit that changes an entity and what is below it, whatever it makes or destroys there: reverting what an instance changed, unlinking it from its prefab, making a prefab of entities. The command takes the branch as it was and as it is after change, and undoing destroys what the change made and brings back what it destroyed (under the ids they had, so the selection and the other steps of the history still point at them); redoing does the reverse. The fields of entities outside the branch that named something the change destroyed are put back too.

    UnpackPrefabCommand

    Turns an instance into plain entities as one step (): undoing brings the link back with what the instance kept aside, redoing breaks it again.

    UnresolvedAssetCommand

    Drops the reference text that a loaded scene held for an asset field that could not be loaded (see ), and puts it back on undo. It goes together with the edit that clears or replaces such a field: without it the next save would write the old reference again, as if the edit had not happened.

    WorldRef

    The world a command acts on, looked up each time it runs: an editor replaces its world (a play run, then back to editing) and the history has to follow it. A converts to one that is always that world.

    Interfaces¶
