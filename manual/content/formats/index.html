    File formats¶

    Every file the engine makes or reads that is not a format everyone already knows has its own extension, and that extension starts with w: .wscn, .wmdl, .wpak… This page is the reference for all of them: what each holds, how it is laid out, which version it is and which versions a reader takes, and whether the engine reads it today. The formats everyone knows keep their names: .luau, .slang, .rml, .rcss, .glb, .gltf, .png, .jpg, .ogg, .wav, .flac, .mp3, .ttf, .otf, .xsd, and .ktx2 (what an imported image is today).

    Two kinds of format exist, and the engine keeps them apart:

    • XML formats are what people and tools write and read: scenes, prefabs, manifests, import settings, and the formats planned below. They are UTF-8 text, they have an embedded .xsd where the engine reads them today, and a version control system shows and merges them as text. XML is the only authored format: there is no other text format in the engine.
    • Binary formats are what the engine makes for itself: imported models and shaders, packs, and cooked XML. Every one starts with a four-letter magic (the extension in capitals, WXMB for cooked XML), is little-endian, and is never edited by hand; it is made again from its source.

    Status says whether the engine reads the format now. Implemented means the code reads and writes it as described here (this page was written from the code). Planned: not read by the engine yet is a design: the layout may still change when the format is built, and nothing in the engine opens such a file. A game or a tool must not depend on a planned format.

    The table¶

    Extension Holds Form Magic Status
    .wscn a scene: entities, components, prefab instances XML; cooked XML in packs WXMB when cooked implemented
    .wprf a prefab XML; cooked XML in packs WXMB when cooked implemented
    .wimp the import settings, the UID, the hash and the sub-asset UIDs of the source file it sits beside XML none implemented (version 2)
    .wgam a game's manifest (game.wgam) XML none implemented
    .wmod a package's or mod's manifest (mod.wmod) XML none implemented
    .wpak a pack: a game's files, compressed and optionally encrypted binary, own layout WPAK, or a hash of the key implemented
    .wmdl an imported model binary, own layout WMDL implemented (version 1); version 2 planned
    .wshd a compiled shader module binary, own layout WSHD implemented (version 1); on the common container planned
    cooked XML any XML document of a cooked pack, as a tree binary, own layout WXMB implemented
    .ktx2 an imported image (a standard KTX 2 file) binary, Khronos format the KTX 2 identifier («KTX 20») implemented; .wtex takes its place as the imported form with the image import
    .wtex a texture, in a portable form and in a GPU form binary, common container WTEX implemented (version 1); image import does not write it yet
    .wsnd an imported sound binary, common container WSND planned
    .wmat a material and its parameters XML; cooked XML in packs WXMB when cooked implemented
    .wdat one typed data record, referenced by an asset reference XML none planned
    .wcur a curve: float or colour over time XML none planned
    .wloc the strings of one language XML none planned
    .wfnt a font family: faces and fallbacks XML none planned
    .wphy a physics material XML none planned
    .wsfx sound events (and, later, mixer snapshots) XML none planned
    .wgph a generic node graph XML none planned
    .wcol cooked collision shapes of a model binary, common container WCOL planned
    .wanm an animation clip binary, common container WANM planned
    .wagr an animation graph XML none planned
    .wfx a particle effect XML none planned
    .wnav navigation mesh tiles binary, common container WNAV planned
    .wter terrain: an XML header and binary tile blocks mixed to be decided planned
    .wsky a sky and its environment XML none planned
    .wpp a post-process volume XML none planned
    .wsav a save slot XML none planned
    .wwld a world made of streamed scene cells XML none planned
    .wbak baked lighting: lightmaps and probe volumes binary, common container WBAK planned

    Files that are not assets and are not in this table: imported/index.xml and imported/assets.xml (below), the player's user://settings.xml (Settings), the definitions in a package's data/*.xml with their schemas/*.xsd (Definitions and schemas), and the cache of compiled shaders under the user's folder (a private file, WSHC2, which nothing else reads).

    The table is the source of truth. The extensions, the magics, the root elements and the versions of the formats the engine reads are one table in the code (AssetFormats in Weft.Content, see Asset identity), and the importers, the hot reload, the editor, the packer and the readers go by it. A format that is planned below has no row until the code that reads it lands.

    Conventions¶

    • Little-endian, everywhere. A magic is written as the four ASCII letters in this order: WPAK is the bytes 57 50 41 4B. Tables below write offsets from the start of the file.
    • String (in the formats that are not a container): the length in bytes as a 7-bit encoded integer (one byte for under 128, as .NET's BinaryWriter writes it), then the UTF-8 bytes. Vector is its float32 components in turn (Vector3 is 12 bytes), a matrix is 16 float32 in row-major order (M11, M12… M44), and a bool is one byte.
    • UID: uid:// and 13 characters of lower-case Crockford base32, uid://[0-9a-hjkmnp-tv-z]{13} (Asset identity). A UID is 64 random bits and never zero.
    • XML documents are UTF-8 (a byte order mark is allowed). Where a format has a version attribute, a reader refuses a version newer than the one it knows, and says so; a binary format says what it takes in its own section, because some take only the version they were written with. A file that is wrong is a ContentException (or a FormatException for a scene or a prefab) that names the file and, for XML, the line.
    • Names do not convert. A file that still has an extension these formats had before this naming is not read as any of them; see File names.

    Sidecars and artifacts¶

    One pattern holds for everything that is imported from a file made by other tools:

    models/car.glb                       the source: kept, edited in the tool that made it
models/car.glb.wimp                  the sidecar: XML, kept in version control, holds the UID and the import settings
imported/models/car.glb.wmdl         the artifact: binary, made by --import, never edited
    • The source stays where it is and is what artists work on. Nothing in a game needs it once it is imported and cooked.
    • The sidecar is the source's path plus .wimp. It is small, it is XML, and it belongs in version control: the identity (UID) and the settings of an asset are decisions, and a diff of them makes sense. It is made on the first import (Asset import).
    • The artifact is in the imported/ folder at the root of the game or the package, at the path of the source with the extension of the artifact added: imported/<source path>.<extension> (imported/textures/ground.png.ktx2, imported/lit.slang.wshd). There is no suffix to tell it from the source (nothing like a _c): the folder and the extension are enough. The artifact is a cache, so it is made again from the source and the sidecar whenever its key changes (Asset import); a game decides for itself whether it keeps it in version control.
    • A pack holds the same bytes as the folder. --pack --cooked puts each artifact at its path in the pack and leaves out the source and the sidecar (Packs); the UID list imported/assets.xml goes along, so a UID still names its asset. The exceptions are documents: a scene, a prefab and the definitions of the base packages are stored as cooked XML at the path of their source.
    • Models are imported to a binary .wmdl. There is no authored XML model format: the source of a model is a glTF file, and a model that is described in XML instead is only an idea (see wmdl).
    • Authored documents (a scene, a prefab, the planned XML formats) are their own source: they have no sidecar and no artifact, and their UID is the uid attribute of the root element.

    Formats the engine reads today¶

    wscn: scene¶

    Purpose. The entities of a world with their components, as an XML document. The editor saves and opens them, a game's entry scene is one, scripts and tools make and read them. Details and the C# and Luau API: Scenes.

    Layout. The root is <Scene>; the schema is scene.xsd (embedded in Weft.Ecs).

    Part Meaning
    <Scene version uid> version is required by the schema: 1, or 2 when the scene holds a prefab instance. uid is the file's identity, optional (text made by SaveScene has none; a saved file has one).
    <Components> optional; the components that scripts defined, each <Component name> with <Field name kind [assetType]> children. Components of the engine and the game are not listed.
    <Entity id name [prefab]> an entity, any number. id is its number in the file (from 1). Its children are its components (an element named after the component, one attribute per field, empty for a tag) and its child entities (more <Entity>).
    <Entity prefab="path\|uid"> an instance of a prefab: it holds only what the instance changes: component elements (changes to the root), <Entity> children (added below the root) and <Override entity name remove> elements (changes to any other entity of the instance). 
    <?xml version="1.0" encoding="utf-8"?>
<Scene version="1">
  <Components>
    <Component name="Ticker">
      <Field name="count" kind="Int32"/>
      <Field name="look" kind="AssetRef" assetType="model"/>
    </Component>
  </Components>
  <Entity id="1" name="ground">
    <Transform Position="0 -0.5 0" Rotation="0 0 0 1" Scale="1 1 1"/>
    <ModelRenderer Model="res://models/ground.glb|uid://8c1q0w3e5r7ty"/>
    <Entity id="2" name="crate">
      <Transform Position="1.25 0 0" Rotation="0 0 0 1" Scale="1 1 1"/>
      <Ticker count="3"/>
    </Entity>
  </Entity>
  <Entity id="3" name="camera"><Transform Position="0 2 -6" Rotation="0 0 0 1" Scale="1 1 1"/><MainCamera/></Entity>
</Scene>

    Field text is the same in every culture: true/false, decimal integers, the shortest text that reads back as the same float, vectors and quaternions as numbers separated by spaces, an Entity field as an id of the file (2/3 inside an instance), an AssetRef as path|uid://… (Field text). Loading is forgiving (an unknown component or attribute is logged and skipped); what is an error is a document that is not XML, a root other than <Scene>, and a version newer than the engine's.

    Versioning. The writer produces version 1, and version 2 for a scene that holds a prefab instance, so that an engine that does not know instances refuses the file instead of loading them empty. The reader accepts 1 and 2 and refuses a larger number; a version attribute that is missing is accepted although the schema requires it. A new version is made when a change would make an older engine load a file wrongly.

    In a pack. --pack --cooked stores the scene as cooked XML at the same path; every reader takes both forms (Cooked scenes).

    Status. Implemented. Owning page: Scenes.

    wprf: prefab¶

    Purpose. A piece of a scene that is made again and again: one entity with everything below it, saved as XML. A scene or another prefab holds an instance as one element that names the prefab and says only what it changes. Details: Prefabs.

    Layout. The root is <Prefab>; the schema is prefab.xsd (embedded in Weft.Ecs). The entity elements and the field text are those of a scene.

    Part Meaning
    <Prefab version uid nextId> version is required by the schema (1). uid is the file's identity. nextId is the id the next new entity takes: above every id in the file, never lowered.
    <Components> optional, as in a scene.
    <Entity id name> exactly one, the root; everything else is below it. Unlike a scene's, an id does not change when the file is saved: scenes that instance the prefab name its entities by id.
    <Entity prefab="…">, <Override …> a nested prefab instance, as in a scene. 
    <?xml version="1.0" encoding="utf-8"?>
<Prefab version="1" uid="uid://7h2k4m6p8q0rs" nextId="4">
  <Entity id="1" name="Lamp">
    <Transform Position="0 0 0" Rotation="0 0 0 1" Scale="1 1 1"/>
    <Entity id="2" name="Bulb">
      <Transform Position="0 1.8 0" Rotation="0 0 0 1" Scale="1 1 1"/>
      <Light Color="1 0.9 0.7" Intensity="80" Range="12" InnerCone="0" OuterCone="0" Kind="1"/>
    </Entity>
    <Entity id="3" name="Base"><Transform Position="0 0 0" Rotation="0 0 0 1" Scale="1 1 1"/></Entity>
  </Entity>
</Prefab>

    Versioning. The version is 1. The reader refuses a larger number and accepts a missing version; a nextId that is missing or not above every id is worked out again, with a warning. A file with no root entity or with two is an error.

    In a pack. Stored as cooked XML at the same path by --pack --cooked (Cooked builds).

    Status. Implemented. Owning page: Prefabs.

    wmat: material¶

    Purpose. A material, or an instance of one: the shader template, typed parameters, texture asset references, a few switches, and a parent it overrides. A material says only what it sets, so a child lists only what it changes. The document is read and merged by MaterialAsset in Weft.Content (Materials/); the renderer does not use it yet (it draws the materials of a model as they are in its .wmdl), and a model import does not write .wmat files yet.

    Layout. The root is <Material>; the schema is material.xsd (embedded in Weft.Content). The order of the children is free.

    Part Meaning
    <Material version uid> version is 1. uid is the file's identity: the import adds it, and it stays when the file moves.
    shader the shader template, a .slang module, as an asset reference. Required unless there is a parent, which then supplies it.
    parent another .wmat as an asset reference: this material starts as a copy of it and changes what it names.
    alphaMode, alphaCutoff, doubleSided opaque (the default), mask or blend; the alpha under which a mask pixel is not drawn, 0 to 1 (0.5 by default); and whether both faces of a triangle are drawn (false by default). Left out, a child has its parent's.
    <Float name value> a number.
    <Vec2 …>, <Vec3 …>, <Vec4 …> two, three or four numbers separated by spaces.
    <Color …> a linear color: red green blue, and alpha (1 when left out).
    <Int …>, <Bool …> a whole number (32 bits), true or false.
    <Texture name ref> a texture the shader samples: an image (.png, .jpg), .ktx2 or .wtex, as an asset reference.

    A name starts with a letter or _ and has up to 64 letters, digits and _. It is the name the shader declares; the engine does not check it against the shader. A parameter name is used once, a texture name is used once, and a parameter and a texture may share a name. The names that mirror what a model's material has today are baseColor (color), metallic, roughness, normalScale and occlusionStrength (floats), emissive (a Vec3) and unlit (a bool), with the textures baseColor, metallicRoughness, normal, occlusion and emissive.

    <Material version="1" uid="uid://4k2m9x7q1w3ze" shader="res://shaders/lit.slang" parent="res://materials/base.wmat" alphaMode="mask" alphaCutoff="0.35" doubleSided="true">
  <Color name="baseColor" value="0.8 0.2 0.1 1"/>
  <Float name="roughness" value="0.4"/>
  <Float name="metallic" value="0"/>
  <Vec2 name="uvScale" value="2 2"/>
  <Vec3 name="emissive" value="0 0.5 1"/>
  <Vec4 name="tint" value="1 1 1 0.5"/>
  <Int name="layers" value="3"/>
  <Bool name="receiveShadows" value="false"/>
  <Texture name="baseColor" ref="res://textures/brick.png"/>
  <Texture name="normal" ref="res://textures/brick_n.ktx2|uid://4k2m9x7q1w3zf"/>
</Material>

    Parents. MaterialAsset.Resolve(assets, path) lays the chain over itself, from the top parent down: a parameter or texture of the same name is replaced where it stands, a new one is added after, and a switch the child leaves out is its parent's. The result (ResolvedMaterial) has a value for everything and lists the files it was made from. A child cannot change the type of a parameter (a Float that a parent defines cannot be a Vec3 below it). A parent is found by its path, or by its UID when the file moved. The chain is refused when a parent does not exist or is not a valid material, when it comes back to a material it has been through (a cycle, named with the paths), or when it is more than 8 parents deep.

    Moving files. Every attribute whose whole text is an asset reference is found and rewritten when its file is renamed or moved (Asset identity): the parent, the shader and each <Texture ref>. A UID in a reference is never changed.

    Limits. A document is at most 1 MiB, has at most 256 parameters (of all types together) and 64 textures, and its names are at most 64 characters. The reader refuses anything else the schema does not describe, a number that is not finite or too large for a float, and a document with no shader and no parent.

    In a pack. Stored as cooked XML at the same path by --pack --cooked; MaterialAsset.Load and Parse read both forms.

    Status. Implemented (version 1). Related page: Rendering.

    wimp: import settings¶

    Purpose. The sidecar of a source file: car.glb.wimp sits beside car.glb, holds the asset's UID, remembers what the importer made of it, and changes how it is imported. See Sidecars and artifacts.

    Layout. The root is <Import>; the schema is import.xsd (embedded in Weft.Content). Every attribute is optional; the order of the child elements is free.

    Attribute For Meaning
    version (1) any asset the version of this format: 2. A sidecar without it is version 1
    uid any asset the identity of the asset; written by the first import, never changed by hand. It is not part of the import key: minting or changing it imports nothing again.
    sourceHash any asset the SHA-256 of the source file as the last import read it, 64 lower-case hexadecimal digits; written by the importer, not part of the key
    srgb (true) images colour maps are sRGB; normal maps, roughness and masks are linear
    normalMap (false) images the image is a normal map: linear, and encoded for accuracy
    compression (uastc) images, textures of models uastc or none (8-bit RGBA)
    mips (true) images build the mip chain
    optimize (true) models merge duplicate vertices and reorder for the GPU's vertex cache
    Element For Meaning Used by the engine
    <Variant> with <Define name [value]> children shaders one more version of the shader to compile yes
    <SubAsset name uid/> (up to 4096) models a file the import makes from the asset (material/paint, texture/albedo) and the UID it was given; minted once per name, written by the importer, kept by name through every import yes: the model importer asks for one per material and texture; the files themselves are not written yet
    <MaterialRemap slot ref/> models use the material asset ref (path or uid://, a .wmat) for the model's material slot slot read, not applied yet
    <Socket name node position rotation/> models a named attachment point on a node of the model (empty node is the root); position is x y z (default 0 0 0), rotation a quaternion x y z w (default 0 0 0 1) read (ImportSettings.Sockets), not written into the model yet
    <Clip name loop start end/> animation a named part of the source's animation, start/end in seconds kept, not read by anything
    <Lod screenSize reduction/> models a level of detail: from this share of the screen's height, this share of the triangles taken away kept, not read by anything
    <Collision shape/> models none, box, convex or mesh kept, not read by anything 
    <Import version="2" uid="uid://4k2m9x7q1w3ze" sourceHash="9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08" srgb="false">
  <SubAsset name="material/paint" uid="uid://0123456789abc"/>
  <MaterialRemap slot="paint" ref="materials/paint.wmat"/>
  <Socket name="hand" node="arm.R" position="0 0.1 0" rotation="0 0 0 1"/>
  <Clip name="walk" loop="true" start="0" end="1.5"/>
  <Collision shape="convex"/>
</Import>

    <Import>
  <Variant><Define name="SHADOWS"/><Define name="QUALITY" value="3"/></Variant>
</Import>

    Versioning. The reader accepts version 1 (no version attribute) and 2, and refuses a larger number ("written by a newer engine"). The next import of an asset rewrites its sidecar as version 2, in the same file: the engine edits the text (the root's attributes and the <SubAsset> elements), so comments, layout, quotes, line endings and every element it does not use stay character for character; there is no command and no other migration. The settings, minus the attributes and elements the importer writes (uid, version, sourceHash, <SubAsset>), are part of the import key, whose version is AssetImporter.ImporterVersion (4): when the importer changes what it writes, that number goes up and every artifact is made again.

    Limits. A sidecar over 1 Mi characters, with more than 4096 sub-assets, a repeated UID or name, a UID that is not one, or an unknown element or attribute is refused with a message that names the file.

    Status. Implemented (version 2): uid, sourceHash, <SubAsset>, <Variant> and the settings are written or read by the engine; <MaterialRemap> and <Socket> are read and available to the model importer and will be applied by the model steps that follow; <Clip>, <Lod> and <Collision> are validated and preserved and have no reader yet. Owning page: Asset import; the UID: Asset identity.

    wgam: game manifest¶

    Purpose. What a game is called, who made it, which version it is, where the player's files go, its Steam app id and what its window looks like. It is the file game.wgam at the root of a game folder. Details: The game manifest.

    Layout. The root is <Game>; the schema is game.xsd (embedded in Weft.Content).

    Part Meaning
    <Game name organization version [executable identifier userFolder steamAppId description copyright]> name, organization and version (major.minor.patch) are required
    <EntryScene path/> the scene loaded before the packages' scripts run
    <Icon path/> a square PNG, 256 pixels or more
    <Window width height fullscreen resizable/> the window the game opens with 
    <Game name="Fixture Game" organization="Weft" version="1.0.0" executable="FixtureGame" identifier="org.weft.fixturegame">
  <EntryScene path="scenes/main.wscn"/>
  <Icon path="icon.png"/>
  <Window width="1280" height="720" fullscreen="false" resizable="true"/>
</Game>

    Versioning. The file has no format version: the schema is the format, and a change that adds an optional attribute or element is compatible. The version attribute is the game's version, which the gameVersion ranges of mods are checked against. A game.wgam that does not match the schema, or breaks a rule it cannot say (a path with .., an icon that is not square), is an error of the game: it does not start.

    Status. Implemented. Owning page: The game manifest.

    wmod: package manifest¶

    Purpose. What a package is (the base game's, or a mod's), what it needs and what it brings. It is the file mod.wmod at the root of a package folder, of a .zip, or of a Workshop folder. Details: Packages and mods.

    Layout. The root is <Mod>; the schema is mod.xsd (embedded in Weft.Content).

    Part Meaning
    <Mod id version [name author description apiVersion gameVersion]> id (lowercase letters, digits, _, up to 64) is the name of the package's folder; version is major.minor.patch; apiVersion (default 1) is the package API it was written for; gameVersion is a version range (default any)
    <Dependency id [version]/> a package that must be there, and a version range of it
    <Script path/> a .luau file run when the package loads, in the order written
    <Content path/>, <Schema path/> a folder of definitions (.xml), a folder of schemas (.xsd) 
    <Mod id="bigger_crates" name="Bigger Crates" version="1.2.0" author="Ada" apiVersion="1" gameVersion="&gt;=1.0 &lt;3">
  <Dependency id="base_game" version="^1.0"/>
  <Script path="main.luau"/>
  <Content path="data"/>
  <Schema path="schemas"/>
</Mod>

    Versioning. The file has no format version. apiVersion is the version of the package API (what a script and a definition can rely on), not of this format: a package that needs a newer one than the engine has does not load, with a reason the game can show. A manifest is never cooked: it stays text so that players and tools can open it.

    Status. Implemented. Owning page: Packages and mods.

    wpak: pack¶

    Purpose. A game's files in one file or a few: each zstd-compressed when that pays, optionally sealed with AES-256-GCM, with an index of paths. A shipped game's res:// is its packs. Details, the key and what encryption does and does not do: Packs.

    Layout. One part is a file; a pack bigger than its limit goes on in name_001.wpak, name_002.wpak… (up to 1000 parts; a file is never split). Each part:

    Offset Size Field
    0 4 magic: WPAK without a key; with a key the first four bytes of SHA-256("Weft pack magic" + key) (changed if that is WPAK or 0), so that an encrypted pack has no signature
    4 4 format version (u32): 1
    8 4 flags: 1 = the index is sealed, 2 = another part follows
    12 4 zero
    16 8 offset of the index
    24 8 stored length of the index
    32 8 raw length of the index
    40 4 number of files in this part
    44 4 zero
    48 32 random salt of the part
    80 … the files' data, each aligned to 16 bytes, then the index

    The index is zstd-compressed (level 19) and, with a key, sealed. Raw, it is a u32 count and, per file: the path (a string), u8 flags (1 = compressed with zstd, 2 = sealed, 4 = removed: the path is taken away from the packs below this one, and has no data), i64 offset, i64 stored length, i64 raw length and 16 bytes (the start of the SHA-256 of the raw file). A file is compressed when it has 64 bytes or more and that saves at least 10%; compression comes first and encryption after. A sealed blob is nonce (12) | tag (16) | ciphertext (AES-256-GCM), with the file's path as associated data so that it cannot be moved to another path; the key of a part is HKDF-SHA256(pack key, salt). A later part overrides an earlier one, and a patch pack mounted over a base replaces, adds and removes.

    Versioning. The version is 1 and the reader takes exactly that: any other number is refused with the version it found. A change of layout makes a new number.

    Planned. A later version of the index may add a dependency table per file (which other files an asset needs), so that a loader can read what a scene needs before it asks for it. Nothing reads or writes it yet.

    Status. Implemented. Owning page: Packs.

    wmdl: model¶

    Purpose. A glTF model after import (ModelData): ready to load without a glTF parser or any image decoding. Vertex and index buffers use meshoptimizer's lossless codecs (the geometry comes back bit for bit), and the textures are embedded as KTX 2 files. It is made by --import as imported/<path>.wmdl (Asset import); ContentLoader loads it in place of the glTF.

    Layout (version 1). ModelFile. A single stream, in this order; a count is i32, and a blob is an i32 length and that many bytes.

    Part Fields
    Header magic WMDL (u32), version (u32, 1), name (string), bounds minimum and maximum (two Vector3)
    Textures count; per texture: name (string), srgb (bool), filter (u8), mipmaps (bool), wrap U and wrap V (u8 each), a blob holding a KTX 2 file
    Materials count; per material: name, base colour factor (Vector4), base colour texture, metallic factor, roughness factor (f32), metallic-roughness texture, normal texture, normal scale, occlusion texture, occlusion strength, emissive factor (Vector3), emissive texture, alpha mode (u8), alpha cutoff (f32), double-sided (bool), unlit (bool)
    Meshes count; per mesh: name, material index (i32), bounds (two Vector3), vertex count, index count, a blob of vertices (meshoptimizer vertex codec, 48-byte vertices), a bool (the indices are a triangle list), a blob of indices (meshoptimizer index codec for a triangle list, raw u32 otherwise)
    Instances count; per instance: mesh index (i32), world matrix
    Lights count; per light: name, kind (u8), colour (Vector3), intensity, range, inner cone, outer cone (f32), position, direction (Vector3)

    A texture reference in a material is a bool (present), then the texture index (i32), the UV set (i32), offset and scale (Vector2) and rotation (f32). Counts and blob lengths are checked against the size of the file before anything is allocated for them: a damaged file is a ContentException that names it, never anything else.

    Versioning. The version is 1 and the reader takes exactly that; any other is refused with "import it again". Importing is cheap to repeat, so no older version is kept readable.

    Planned: version 2. A model on the common container: a small META block (name, bounds, meshes and submeshes, material slots with their parameters and an optional .wmat remap, texture references by sub-asset UID, nodes, sockets, a table of levels of detail) and a pair of buffer blocks per mesh (VTX<n>, IDX<n>, with the same meshoptimizer codecs), deterministic, readable by --dump. The textures leave the file and become sub-assets, imported/<model path>/<n>.wtex, each with a UID kept in the model's sidecar. Version 1 would not be read: the model is imported again. An authored XML model format, to describe a model without a glTF file, is only an idea: no engine code reads one.

    Status. Implemented (version 1). Owning page: Asset import.

    wshd: shader¶

    Purpose. A Slang shader module compiled ahead of time, so that a shipped game never loads the compiler: imported/<path>.wshd. One file serves Vulkan and Metal. See Compiled ahead of time and Asset import.

    Layout (format version 1). ShaderBundle. A single stream, strings and i32 counts as in wmdl.

    Part Fields
    Header magic WSHD (u32), format version (i32, 1), shader ABI (i32, 2), module name (string), variant count
    Per variant the variant's name (its defines sorted by name as A=1;B=2; empty for the default one), the reflection (the compiler's description of the shader's parameters and entry points, as text), the compiler's warnings (string), the number of code blobs
    Per code blob backend (u8: 1 SPIR-V, 2 Metal shading language source, 3 DXIL, reserved: nothing writes it), entry point name (string), length (i32) and the code

    A reader takes the code of the backend it runs on and skips the others. The reflection is that of the first backend written (SPIR-V).

    Versioning. Two numbers. The format version (1) is the layout above; the shader ABI (2) is what compiled code assumes about the engine (the bindless descriptor layout and the push constants every pipeline shares), and goes up whenever that changes. A reader takes exactly its own number of each: a bundle of another ABI is refused with "import it again", not left to crash the driver. (A cache of compiled shaders under the user's folder is a separate private file, WSHC2; it is not a format of the engine's content.)

    Planned. The bundle on the common container: one block per target (SPIR-V, Metal) and one for the reflection, a bumped format version, and a dumper for --dump.

    Status. Implemented. Owning pages: Asset import, Graphics.

    Cooked XML (WXMB)¶

    Purpose. The tree of any XML document in a binary encoding, so that a shipped game parses no text for its scenes, prefabs, definitions and UID list. --pack --cooked stores such a document in place of its source, at the same path. It is not typed by the reflection registry: it holds the XmlNode tree, so it does not depend on which components the engine had when the file was cooked. A tree is read back as it was written. See Cooked XML.

    Layout (version 1). XmlBinary. Little-endian; a varint is an unsigned 32-bit LEB128 (7 bits per byte).

    Part Fields
    Header, 16 bytes magic WXMB (u32), version (u16, 1), flags (u16, none defined: 0), string count (u32), element count (u32)
    Strings per string: byte length (varint), UTF-8 bytes; in the order the writer first used them; string 0 is the empty string
    Elements in document order, root first: name (varint, a string index), line (varint), attribute count (varint), per attribute: name and value (varint string indexes), text (varint string index), child count (varint)

    The same tree always gives the same bytes. The origin of an element is not stored: the reader gives every element the path it was asked to read, so an error still names the file and the line. Every count is checked against the bytes left before the reader makes room for it, and nesting is limited as in the text parser.

    Versioning. The reader takes every version from 1 up to the one it knows; a file from a newer engine, version 0, or a flag this engine does not know is refused with "cook again". A text XML file can never be mistaken for it: those begin with <, a byte order mark or white space, and XmlFile.Read tells them apart by the magic.

    Status. Implemented. Owning page: Asset import.

    ktx2 textures¶

    Purpose. An imported image today. A .png or .jpg is imported to imported/<path>.ktx2, a standard Khronos KTX 2 file with its whole mip chain: Basis Universal UASTC blocks (one file for every platform, transcoded at load to BC7, ASTC 4x4 or RGBA8, whichever the GPU samples), or 8-bit RGBA with compression="none". Either way the levels are supercompressed with zstd. The textures embedded in a .wmdl are the same files. Because it is a standard container, any KTX 2 tool opens it.

    Layout. As the KTX 2 specification: an identifier («KTX 20», then \r\n\x1A\n), a header, a level index (the smallest level first in the file), a data format descriptor that says what the bytes are (colour space included) and the levels. Details of what the importer writes and its settings: GPU texture compression.

    Versioning. KTX 2 is versioned by Khronos; libktx reads it. The engine's own part is the importer's fingerprint (the encoder settings), which is part of the import key.

    Planned. .wtex replaces this form: wtex, which reads and writes the same level bytes and converts to and from a .ktx2. A .ktx2 would then be an importable source, not an artifact.

    Status. Implemented. Owning page: Asset import.

    wtex: texture¶

    Purpose. One container for every texture, in two forms: a portable form that import writes (UASTC blocks, transcoded at load as today) and a GPU form that export writes (blocks the GPU samples directly, so there is no transcoding at load).

    Why not stay with KTX 2: it already gives a level index with the smallest level first, per-level zstd, key/value data, the colour space in the descriptor, and it can hold BC7, BC5, BC6H and ASTC payloads. What an own container adds is: the same header, UID, import hash, --dump and reader as every other artifact; mips aligned to 4096 bytes (KTX 2 aligns levels to the block size), a resident tail (all mips of 64 KiB or less in one block at the front, so one read gives a usable texture) and typed engine fields instead of key/value strings; and a GPU form that is read without libktx, uploaded straight from the decompressed span into the staging buffer. The cost is that KTX tools cannot open a .wtex; the payload is the same bytes a KTX 2 level holds, so a .wtex and a .ktx2 convert to each other by rewrapping (--dump x.wtex --ktx2 out.ktx2).

    Layout. On the common container, magic WTEX, format version 1 (WtexFile in Weft.Content). The header's flags are the texture's flags too, so that a tool that has read only the first 64 bytes knows whether the file is portable; a file where the two differ is refused.

    META is 48 bytes, little-endian, the same size in every file of version 1 (a reader refuses any other size):

    Offset Field Size Meaning
    0 width u32 of the first level, 1 to 16384
    4 height u32 of the first level, 1 to 16384
    8 depth u32 1 unless the texture is 3D, then 2 to 2048
    12 layers u32 1 unless the texture is an array (Array), then 1 to 2048
    16 faces u32 1, or 6 for a cube map (Cube)
    20 mip count u32 1 to 15, and at most the length of the full chain of the largest of width, height and depth
    24 flags u32 see below
    28 payload u8 0 Uastc, 1 Rgba8, 2 Bc7, 3 Bc5, 4 Bc4, 5 Bc6hU, 6 Rgba16f
    29 texture group u8 0 World, 1 Character, 2 Ui, 3 Effects, 4 Lightmap: a quality setting per group
    30 LOD bias s8 how many mip levels the quality setting drops more (positive) or fewer (negative) for this texture
    31 tail mip u8 the first mip level that is in TAIL, 0 to mip count minus 1
    32 alpha cutoff f32 the coverage reference for AlphaCoverage, 0 to 1 (0.5 unless the importer says otherwise)
    36 filter u8 0 nearest, 1 linear
    37 mipmaps u8 0 or 1: whether the mip levels are sampled
    38 wrap U u8 0 repeat, 1 mirrored repeat, 2 clamp to edge
    39 wrap V u8 the same
    40 reserved 8 bytes zero (a reader refuses anything else)

    The sampler fields are hints for a texture used by itself; a model's material slot may override them. Flags (in code WtexTraits: an analyzer does not allow a type to be named …Flags):

    Bit Flag Meaning
    0 Portable the file is an import form: a cooked game holds the GPU form of it instead
    1 Srgb the colours are sRGB (the format the GPU samples is an sRGB one)
    2 NormalMapRG a normal map: the first two channels hold the normal
    3 AlphaCoverage the alpha is a coverage that mips keep, against the alpha cutoff
    4 Premultiplied the colour channels are multiplied by alpha
    5 Hdr high dynamic range: set exactly when the payload is Bc6hU or Rgba16f
    6 Cube set exactly when there are six faces
    7 Array the layers are separate images (without it there is one layer)

    Other combinations are refused: a bit this engine does not know; UASTC without Portable (UASTC is only the portable form; the other payloads may be either); Srgb for a payload that is not colour (Bc5, Bc4, Bc6hU, Rgba16f) or together with NormalMapRG; a cube map that is not square; a 3D texture that is an array or a cube map.

    Levels. What each payload is, the same bytes a KTX 2 file holds:

    Payload One block Vulkan format
    Uastc 4x4 texels in 16 bytes undefined (0): a KTX 2 file says UASTC in its descriptor
    Rgba8 1 texel in 4 bytes R8G8B8A8_UNORM (37), _SRGB (43)
    Bc7 4x4 in 16 bytes BC7_UNORM_BLOCK (145), _SRGB_BLOCK (146)
    Bc5 4x4 in 16 bytes BC5_UNORM_BLOCK (141)
    Bc4 4x4 in 8 bytes BC4_UNORM_BLOCK (139)
    Bc6hU 4x4 in 16 bytes BC6H_UFLOAT_BLOCK (143)
    Rgba16f 1 texel in 8 bytes R16G16B16A16_SFLOAT (97)

    Level n is the texture with width, height and depth halved n times (never under 1), and is ceil(w/bw) * ceil(h/bh) * bytes * depth * layers * faces bytes: no padding in a row, a level or between its images, which follow each other layer by layer, then face by face, then slice by slice (as a KTX 2 level does). A reader checks the size of every block against this before it allocates.

    Blocks. META, then TAIL, then MIP<n> for each level below the tail from the largest of the tail's neighbours down to 0: exactly these, in this order, so a file read from its start is progressively usable (smallest first, as a streamer reads it). A reader refuses a file that has another set of blocks, another order, a codec that is not for pixels (only none and zstd are), flags in a block row, or a block aligned to less than 4096 bytes.

    • TAIL holds the levels from the tail mip on, the smallest first, one after the other with nothing between them, so that the offset of every level is a multiple of the size of its block (as a buffer offset for an upload has to be). A writer puts into the tail every level of 64 KiB or less, and always the last level; so a small texture is only a tail, and a texture of one big level has a tail of that level. A reader takes any tail index: the 64 KiB is the writer's rule. The tail is stored as it is (no codec): it is small, read at once, and can be mapped.
    • MIP<n> holds level n (all faces and layers) and is compressed with zstd (level 12 unless the writer is told another, or told 0 for none). The kind has room for one character after MIP, so n is written as a hexadecimal digit: MIP0 to MIP9, MIPA to MIPE (a texture has at most 15 levels).
    • Every block but META is aligned to 4096 bytes and holds raw bytes whose CRC-32C is in the table; the CRC is checked every time a level is read.

    Forms. Import writes the Portable form: UASTC, or RGBA8 for compression="none" and for textures under 4 pixels (and, later, BC6H or half-float RGBA for HDR). The development runtime, and mods (which are never cooked), transcode a portable texture at load, as a .ktx2 is today. --pack --cooked and export rewrite every portable texture to the GPU form of the desktop profile: colour to BC7, normal maps (NormalMapRG) to BC5, single-channel masks to BC4. Every desktop Vulkan GPU, lavapipe and Apple's Macs have BC; a GPU form met by a GPU without it is a ContentException that says so. The result is cached by import hash (imported/.cooked/<hash>.wtex, an export cache, not kept in version control). The GPU form is 10 to 30 percent bigger on disk than RDO-compressed UASTC with zstd; that is accepted for no work at load.

    KTX 2. WtexFile.ToKtx2() writes the texture as a KTX 2 file and WtexFile.FromKtx2 and ReadKtx2 read one; Weft.Runtime --dump x.wtex --ktx2 out.ktx2 writes the file after the text dump.

    • wtex to KTX 2 (Ktx2Writer): the levels are the same bytes, without supercompression, smallest first in the file, each at a multiple of the size of its block, with the Vulkan format of the table above, a type size of 2 for Rgba16f and 1 for the others, pixelDepth and layerCount 0 when the texture is neither 3D nor an array, and six faces for a cube map. The data format descriptor is the one libktx writes for the format (a test compares the bytes), and for UASTC the one its encoder writes for a texture with alpha (the UASTC model, the RGBA channel, the sRGB or linear transfer function, the premultiplied bit; the encoder says RGB for an opaque texture, which a wtex does not remember, and the two transcode the same). What a KTX 2 file does not keep is the engine's own fields: the group, LOD bias, alpha cutoff, sampler hints, NormalMapRG and AlphaCoverage.
    • KTX 2 to wtex: UASTC (with or without zstd supercompression: libktx inflates it, and the bytes after that are the level), RGBA8, BC7, BC5, BC4, BC6H and half-float RGBA in the formats above; 2D, 3D, cube map and array. ETC1S (BasisLZ), zlib, 1D textures, a file that asks for its mips to be generated, and every other Vulkan format are refused. The flags that follow from the file are set: Portable for UASTC and RGBA8 (the forms a cooked game rewrites), Srgb from the Vulkan format (from the transfer function of the descriptor for UASTC), Premultiplied from the descriptor, Hdr, Cube and Array; the caller adds the rest, and the group, bias, cutoff and sampler (WtexSettings). The header and the level index are checked against the limits above and against the sizes of the levels before libktx reads the file, so that a hostile file cannot make it inflate more than the texture needs.

    Hostile input. The container's checks (sizes against the length of the file before allocation, blocks in order and not overlapping, a total of at most 4 GiB, a CRC for every block) and, on top of them: every number of META is judged against the limits above before any size is computed from it (no field is trusted: a width of four billion is a refused file, not an allocation), the sizes of the blocks must be exactly the ones the shape implies (a level over 1 GiB, or levels over 4 GiB together, are refused), and a damaged block is found when its level is read, not when the file is opened. Anything wrong is a ContentException that names the file.

    Dump. --dump writes width, height, depth, layers, faces, mips, payload, vk_format, form (portable or gpu), flags, group, lod_bias, alpha_cutoff, sampler, tail_mip and one line per level (level 3 = 128x128, 65536 bytes, in TAIL+0, or in MIP3) after the container's block table. A texture whose META is not valid says invalid = and why; the table of blocks is still there.

    Versioning. The format version in the container header; a reader takes the versions it knows (1) and refuses the others, with "Update the engine" for a newer one and "import it again" for an older one.

    Status. Implemented: the reader, the writer, the conversion to and from KTX 2 and the dump. Image import still writes .ktx2 and the loaders still read it; writing and loading .wtex comes with image import, and cooking to the GPU form with the packer. Related page today: Asset import.

    The common binary container¶

    Every binary artifact the engine makes, apart from packs and cooked XML, shares one container: .wmdl, .wtex, .wsnd and .wshd, and the planned .wanm, .wcol, .wnav and .wbak. One reader and writer (BinaryAsset and BinaryAssetWriter in Weft.Content), one place for the UID and the import hash, one --dump. The container is implemented, and .wtex is the first format on it (.wmdl and .wshd are still version 1 in their own layouts, and a version-1 file is not mistaken for a container: see below). The container has no extension and no row in the table of formats: each format on it has its own, and its magic is the one in the table.

    Header (64 bytes, little-endian, offsets from the start of the file):

    Offset Field Size Meaning
    0 magic u32 four printable ASCII characters: WMDL, WTEX, WSND, WSHD…
    4 container version u16 1
    6 format version u16 the version of the format inside (of .wmdl, of .wtex…), at least 1
    8 flags u32 the format's: the container gives them no meaning
    12 header size u32 64
    16 block count u32 1 to 4096
    20 block row size u32 40
    24 block table offset u64 64: the table follows the header
    32 UID u64 the asset's UID, copied from the sidecar; 0 = none (the artifact then belongs to a sub-asset that has none, or to a file without a sidecar)
    40 import hash 16 bytes the first 16 bytes of the import key: the settings, the source hash and the importer's fingerprint; zero when there is none
    56 header checksum u32 the CRC-32C of bytes 0 to 55 of the header and the whole block table (so of the UID, the import hash, the flags and every row); a reader refuses a file where it does not hold
    60 reserved 4 bytes zero (a reader refuses anything else)

    Block table. One row of 40 bytes per block, in the order of the file (each block starts at or after the end of the one before, and the first after the table):

    Offset Field Size Meaning
    0 kind u32 four printable ASCII characters (META, VTX0, IDX0, MIP3…); no two blocks have the same
    4 codec u8 0 none, 1 zstd, 2 meshoptimizer vertex, 3 meshoptimizer index
    5 flags u8 the format's
    6 alignment u8 the block starts at a multiple of two to this power from the start of the file; at most 16
    7 reserved u8 zero
    8 offset u64 where the stored bytes start
    16 stored size u64 the bytes in the file
    24 raw size u64 the bytes after the codec is undone (the same as the stored size for codec 0)
    32 CRC-32C u32 of the raw bytes (Castagnoli, the check value of 123456789 is 0xE3069283)
    36 stride u32 the mesh codecs: the size of one element in bytes (a multiple of 4 up to 256 for vertices, 2 or 4 for indices); 0 for the others

    Block 0 is always META: uncompressed, at most 16 MiB, read in one go, a versioned little-endian structure per format whose strings are in a string block. The other blocks (VTX0…, IDX0, MIP3…) are aligned to 4096 bytes by default so that a streamer can read or map them directly; a small block that nobody maps asks for less. A zstd block is one frame that states its size. The index codec may start a triangle at another of its corners (it is the same triangle with the same winding), so the raw bytes of such a block, and its CRC, are what the decoder gives back: the writer decodes once to make them.

    Deterministic. A writer lays the blocks out in the order they were added (META first), each at the next offset its alignment allows, pads with zeros and stores no time stamp: the same input makes the same bytes. That holds for one version of the zstd and meshoptimizer libraries (an importer's fingerprint should include both); the writer asks meshoptimizer for its vertex codec version 1 at level 2 and its index codec version 1 itself, so nothing else that the process set changes the bytes. Block order is the format's to choose, since it is the order of the file: a texture puts its small mips first.

    Hostile input. A file of a mod or a pack is not trusted. A reader checks the header and every row against the length of the file before it allocates anything, and refuses:

    • a file shorter than its header or its table, more than 4096 blocks, a table that is not right after the header, and a header or table whose checksum does not hold (so a flipped bit in the UID, the import hash, the flags or a row is found, whatever it is in);
    • a block outside the file, an offset that is not aligned as the row says, a block that starts before the end of the one before it (so blocks never overlap the header, the table or each other, and the table lists them in the order of the file), two blocks of one kind, a first block that is not META;
    • a raw size over 1 GiB for one block (16 MiB for META), and over 4 GiB for all the blocks together: what a program that reads every block can be made to decode;
    • a row that does not fit its codec: a stored size that is not the raw size without a codec; a stride that is wrong; a block stored in fewer bytes than the codec can ever make (zstd: 32768 to 1, so at most 1 GiB from 32 KiB; the vertex codec: a few hundred to one, a thousand for small strides, by its block structure; the index codec: a byte for each triangle and a 16-byte table);
    • a zstd block that is not exactly one frame, or whose frame does not say the size the row says (checked before anything is allocated), and a block whose CRC does not match.

    META and the header are checked when the file is read, a block when it is read, every time it is read. What a reader allocates for a block is its raw size, never more than 1 GiB, and only after the row passed these checks; a block that really is a gibibyte of zeros in 32 KiB does decode to a gibibyte, which is why the total is limited. The padding between blocks, and anything after the last block, are not checked (the writer writes zeros, and nothing reads them). A block of no bytes has the rules of any other: its offset is aligned, in the order of the file and inside it. Anything wrong is a ContentException that names the file. The reader keeps the memory it is given and does not copy it: META and the blocks without a codec are slices of it, so a file that is memory-mapped must be mapped read-only and private (or copied): a mapping that another process can write to can change after a block was checked.

    Not on the container. A version-1 .wmdl has the magic WMDL and then a 32-bit version, which reads as container version 1 with format version 0: a reader refuses format version 0, so an old file is told to be imported again and never read as a container. A file with a newer container version is refused with the version it has.

    --dump. Weft.Runtime --dump <file> writes an artifact as text on the standard output: for a container the header, the UID, the import hash and one line per block (offset, sizes, CRC and whether it holds), then META as name = value lines by the dumper registered for the magic (AssetDumpers.Register, one per format, added with the format); a cooked XML file as XML text; a pack as its list of files. See the runtime. --dump <file.wtex> --ktx2 <out> writes a texture as a KTX 2 file as well: wtex.

    Packs and cooked XML keep their own layouts (above); only their magics follow the naming.

    Planned formats¶

    Everything from here on is planned: not read by the engine yet. The text says what each format is meant to hold; the names of elements and attributes are fixed when the format is built, with its schema and its tests. Authored formats are XML with a root version, a uid attribute on the root (the asset's identity), an embedded .xsd, and are cooked as cooked XML in a shipped pack.

    wsnd: sound¶

    Purpose. An imported sound: imported/<path>.wsnd for an .ogg, .wav, .flac or .mp3. The audio system reads those four formats from the source today; the artifact would add the sample rate, the channel count, the number of frames, loop points, a loudness gain and a stream flag.

    Layout. On the common container, magic WSND: META with those fields, and a payload block that is either the source's bytes unchanged or, for a sound that is preloaded, 16-bit PCM.

    Status. Planned. Related page today: Audio.

    wdat: data record¶

    Purpose. One typed record that other assets refer to with an asset reference (an enemy's stats, a recipe). The root element names its type, and the type is checked against the package's schemas (schemas/*.xsd). It differs from a definition: definitions are merged tables with no identity, a .wdat is one asset with a UID. A script would load one as a table.

    Layout. XML; the root element is the type's name.

    Status. Planned. Related page today: Definitions and schemas.

    wcur: curve¶

    Purpose. A curve of floats or colours over time: keys (time, value, in and out tangent, interpolation) and pre and post wrap modes. Interpolation is constant, linear or cubic Hermite. A tween could take one as its easing.

    Layout. XML.

    Status. Planned. Related page today: Tweens.

    wloc: string table¶

    Purpose. The strings of one language: keys, text, plural forms by CLDR category, and notes for translators. Tables merge in the order of the packages.

    Layout. XML.

    Status. Planned. No page yet.

    wfnt: font family¶

    Purpose. A font family: its faces (regular, bold, italic, each a reference to a .ttf or .otf), a fallback chain and a default size.

    Layout. XML.

    Status. Planned. Related page today: User interface.

    wphy: physics material¶

    Purpose. Friction, restitution, density, and the sound and effect a surface plays, for a body to take by reference.

    Layout. XML.

    Status. Planned. Related page today: Physics.

    wsfx: sound events¶

    Purpose. A bank of named sound events: each with clips and their weights, volume and pitch ranges, a bus, a 3D range and a cooldown. Later a second kind of root would hold mixer snapshots (bus levels).

    Layout. XML.

    Status. Planned. Related page today: Audio.

    wgph: node graph¶

    Purpose. A generic graph: nodes (an id, a type, a position, properties), pins, links and comments, with a kind that says what the graph is for (a material graph is a .wgph of kind material). The layout is generic; what node types a kind has, and how pins are typed, is up to the feature that uses it.

    Layout. XML. A reader checks that node ids are unique, that every link names an existing pin and that no link is repeated.

    Status. Planned. No page yet.

    wcol: collision shapes¶

    Purpose. The cooked collision shapes of a model: convex hulls, a mesh BVH, in the physics library's binary form. Today shapes are built when a body is made.

    Layout. On the common container, magic WCOL; kept apart from a physics material because an authored setting and a cooked result differ.

    Status. Planned. Related page today: Physics.

    wanm: animation clip¶

    Purpose. A clip: tracks (compressed with meshoptimizer), events and root motion.

    Layout. On the common container, magic WANM.

    Status. Planned. No page yet.

    wagr: animation graph¶

    Purpose. An animation graph: blend trees, state machines and parameters, laid out as a .wgph with states.

    Layout. XML.

    Status. Planned. No page yet.

    wfx: particle effect¶

    Purpose. A particle effect: emitters, modules and curves (references to .wcur).

    Layout. XML.

    Status. Planned. No page yet.

    wnav: navigation mesh¶

    Status. Planned. No page yet.

    wter: terrain¶

    Purpose. Terrain: an XML header (size, layers, materials) and binary tile blocks (height, splat).

    Files that belong to no asset¶

    These are caches and records that the tools write; they have no UID and no schema of their own in the table above.

    • imported/index.xml: which source each artifact came from and which files it was made from, so that only what changed is imported again. The root is <Imports version>, and version is AssetImporter.ImporterVersion (4). The reader does not check it: the number is also part of every import key, so a new one makes every artifact stale. Each <Import source artifact key> has <Dependency path/> children. A missing or damaged index is read as empty, and everything is imported again.
    • imported/assets.xml: the list of UIDs and paths of the imported assets, sorted by path: <Assets version="1"> with <Asset uid path/> children. It is a copy of what the sidecars and the authored documents hold, to make lookups fast; a pack carries it as cooked XML, and in a cooked pack it is the only record of the imported assets' UIDs. A missing, damaged or newer list is read as empty.
    <Imports version="4">
  <Import source="models/car.gltf" artifact="imported/models/car.gltf.wmdl" key="9c1e…">
    <Dependency path="models/car.bin"/>
  </Import>
</Imports>

    <Assets version="1">
  <Asset uid="uid://4k2m9x7q1w3ze" path="res://models/car.gltf"/>
</Assets>
